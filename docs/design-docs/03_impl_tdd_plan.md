## 개정 2 — provider_id 정규화 경계값 명세 [잔여조건 2]

F4-1을 parameterized test로 확장. 정규화 규칙: 원문을 소문자화 후 `[a-z0-9]`만 잔류.

| 케이스 | 입력(원문 provider_id) | 정규화 결과 | 기대 처리 |
|---|---|---|---|
| F4-1a 대문자 | `Kakao12345` | `kakao12345` | 소문자화 |
| F4-1b 특수문자 혼합 | `user-99_@!` | `user99` | 특수문자 제거 |
| F4-1c 숫자만 | `1234567890` | `1234567890` | 그대로 |
| F4-1d 정규화 후 빈 문자열 | `___---!!!` | `` (빈값) | **예외 처리**: 빈 결과 시 원문 해시(예: SHA-256 앞 12자) 대체 |
| F4-1e 충돌(서로 다른 원문→같은 결과) | `AB-12` vs `ab_12` | 둘 다 `ab12` | **충돌 방어**: 정규화 결과가 아니라 원문 provider_id를 UNIQUE 키로 저장. 대체 이메일에만 정규화 적용하되, 이메일 충돌 시 원문 해시 suffix 부가 |

**핵심 설계 확정**:
- 회원 식별 UNIQUE는 **원문 provider_id** 기준 (정규화 결과 아님) → F4-1e 충돌 원천 차단
- 정규화는 **대체 이메일 로컬파트 생성에만** 사용
- 정규화 결과가 비거나(F4-1d) 이메일 충돌 시 원문 해시 suffix로 유일성 보장

검증: 5케이스 각각 정규화 결과 일치 + F4-1d 예외처리 + F4-1e 두 계정이 별도 members 행
